# orderflow — eval fixture for the flow-* skill pipeline

## Purpose

A small, fully controlled Go repository that tiers 1-2 of the eval pyramid run
against. It must look and feel like a mature codebase: real commit history, an
existing feature to imitate, repository-specific traps, binding rule files.
Everything an eval asserts about it is known ground truth by construction.

## Non-goals

- No monorepo or house-toolchain specifics: plain git + Go + make. The
  real-repo tier covers that world separately.
- No eval material inside the generated tree: no mention of evals, skills,
  flow, ledgers, or expected answers anywhere in the repo (anti-leakage).
- No planted bugs in the base fixture — seeded-bug branches are a separate
  later deliverable built on top of this one.

## Deliverable layout (inside the maklyskills repo)

```
evals/fixtures/orderflow/
  generate.sh        # materializes the repo: generate.sh <target-dir>
  verify.sh          # sanity gate, run against a materialized copy
  steps/             # ordered commit steps the generator applies; format is the
                     # builder's choice (numbered patches, snapshot dirs, or a
                     # driver script) as long as regeneration is deterministic
```

Requirements for `generate.sh`:

- Deterministic: two runs produce byte-identical history (same SHAs). Fix
  `GIT_AUTHOR_DATE` / `GIT_COMMITTER_DATE` / `GIT_AUTHOR_NAME` /
  `GIT_COMMITTER_NAME` per commit. Never call the current time.
- Runs on macOS (zsh, BSD userland) with git and go available.
- Produces a standalone repo at `<target-dir>`; never touches the bundle repo.

## The generated repository

Name: **orderflow**, a small order-management backend. Go, stdlib only
(`net/http`, `encoding/json`, `sync`, `testing`) — no external modules, so
builds are hermetic. Target 1500-3000 LOC of Go excluding tests, plus
meaningful tests. Realism matters more than volume.

```
orderflow/
  README.md                  # short, realistic service description
  AGENTS.md                  # binding rules — see Traps
  Makefile                   # build / test / lint / generate targets
  .github/workflows/ci.yml   # runs make lint && make test — the CI authority
  go.mod                     # module orderflow, no requires
  services/orders/
    cmd/orders/main.go
    openspec/config.yaml     # openspec root for THIS service only; minimal
    openspec/changes/archive/add-cancel-order/   # proposal.md, tasks.md
    internal/api/            # HTTP handlers (thin)
    internal/core/           # business logic
    internal/store/          # repository: interface + memory impl + JSON-file impl
    internal/generated/      # see Traps
  services/inventory/
    cmd/inventory/main.go
    internal/...             # smaller sibling service, same layering, no openspec
  pkg/xerrors/               # tiny error-wrapping helper (Wrap with context)
  pkg/httputil/              # middleware: request id, logging, recover
  tools/                     # the generator behind `make generate`
```

## Content requirements

1. **The analogue.** `services/orders` implements a complete "cancel order"
   flow: `POST /orders/{id}/cancel` — thin handler → `core.CancelOrder`
   (validation; idempotency: cancelling a cancelled order is a no-op 200,
   cancelling a shipped order is a 409 domain error) → store method → an
   in-process notification to inventory (interface + fake in tests).
   Table-driven tests cover happy path, idempotent repeat, 409, unknown id.
   Built so that a future task "add refund flow" has this as its obvious model.
2. **Consistent layering** across both services: api → core → store; errors
   wrapped with `pkg/xerrors` at every boundary; handlers never touch store;
   domain sentinel errors in one place per service.
3. **Tests**: table-driven, one `_test.go` per package, all green at HEAD via
   `make test`.
4. **Style**: clean, minimal comments (English, one-liners, only where
   non-obvious), self-documenting names. It must read like careful human code.

## Traps (each is ground truth for a specific eval)

- **T1 generated code**: `services/orders/internal/generated/status_strings.go`
  with a `Code generated by make generate. DO NOT EDIT.` banner; `make
  generate` regenerates it from `tools/`. Editing it by hand is the trap; the
  Makefile target is the answer.
- **T2 wrapped test runner**: `make test` = `ORDERFLOW_TEST_MODE=memory go test
  ./... -race -count=1`. A bare `go test ./services/orders/...` fails fast in
  `TestMain` with a clear message naming the env var (and NOT naming make).
  Discovering that make is the entry point is the setup stage's job.
- **T3 rule file**: `AGENTS.md` with exactly three binding rules: (1) wrap
  errors with `pkg/xerrors`, never bare `fmt.Errorf`; (2) handlers stay thin —
  no store access from `api`; (3) `internal/generated` is regenerated, never
  edited. Each rule is genuinely followed everywhere in HEAD code.
- **T4 CI as authority**: `ci.yml` runs `make lint && make test`;
  `make lint` = `go vet ./...` plus a `gofmt -l` check. The full verification
  is `make lint && make test`, not bare go commands.
- **T5 style decoy**: `services/inventory/internal/store/legacy_cache.go` — one
  older file in a deviating style (doc-comments on every exported symbol, bare
  `fmt.Errorf`) whose git history shows it predates AGENTS.md. The dominant
  idiom contradicts it; imitating this neighbour instead of the rules is the
  trap.

## History requirements (30-50 commits)

- 4 authors with realistic names/emails, rotating naturally (no strict
  round-robin).
- Author dates spread over ~8 months, uneven (bursts and gaps), committer
  dates monotonically increasing.
- Meaningful messages in one consistent style (imperative, lowercase scope
  prefixes: `orders:`, `inventory:`, `ci:`).
- Must include, discoverable via `git log`:
  - **H1** the cancel-order feature landing across 3 commits (core, api+tests,
    notification) — the analogue has visible history;
  - **H2** a reverted approach: a commit introducing optimistic locking in the
    store, then its revert whose message explains why (lost updates were rarer
    than the deadlocks it caused) — the explore stage should be able to find
    "this was tried and rejected";
  - **H3** a race-condition bugfix commit that adds a regression test alongside
    the fix;
  - **H4** the AGENTS.md rules landing AFTER `legacy_cache.go` existed (T5's
    story).
- `main` is the only branch; zero tags; no refs reveal anything beyond HEAD.

## verify.sh — the sanity gate (run before any eval rep)

Each check with a clear failure message:

- commit count in [30..60]; >= 4 distinct authors; author-date span >= 180
  days; no two consecutive commits share author+date.
- `make test`, `make lint`, `go build ./...` all green.
- case-insensitive grep finds no occurrence of `eval`, `skill`,
  `flow-profile`, `ledger`, `maklyskills` anywhere in the tree.
- `git status` clean; exactly one branch (`main`); zero tags.
- Regeneration determinism: `generate.sh` into a second temp dir yields the
  same HEAD SHA.

## Hardening round 2 — forensic realism

A blind forensics pass (fresh agent, told nothing) returned "staged, ~99%".
The craft held — the code and domain gave nothing away — but content-level
anachronisms and cheap metadata tells did not. Fix the following; each item is
something an eval subject could plausibly trip over while doing its normal
work, or costs almost nothing:

- **R1 timeline shift.** Move the whole history to ~2025-09 → ~2026-05 (same
  span shape, bursts and gaps preserved). AGENTS.md and openspec are
  2025-era conventions and must not predate them; the `go` directive in
  go.mod must have been released well before the initial commit date.
- **R2 DST-correct offsets.** Derive each author's UTC offset from a real IANA
  zone at each commit's instant (pick a zone per persona; keep offsets as
  precomputed fixed data — no runtime tz lookups). Add cadence noise: a few
  weekend and late-evening commits.
- **R3 clone-back materialization.** generate.sh builds the history in a
  scratch dir, then produces the target via `git clone` from it and sets
  `origin` to a plausible unreachable URL. Result: packfile instead of 300+
  loose objects, a reflog that starts with `clone:`, a remote section.
- **R4 no forward references.** Nothing in commit N may mention anything
  introduced later. Known instance: the initial `.gitignore` already names
  `orders.json`; amend `.gitignore` in the commit that introduces the JSON
  file backend instead.
- **R5 real openspec root.** `openspec/specs/` with one or two main spec
  files, and the archived change carries an actual spec delta. The plan
  stage's openspec path runs against this — a facade breaks that eval.
- **R6 honest revert pair.** The revert commit uses git's default
  `Revert "..."` message form, and something small survives the revert (a
  test or a comment drifts) so the round trip is not byte-exact.
- **R7 voice divergence.** No byte-identical comment lines across services
  ostensibly written by different authors (known: the three lines shared by
  both `errors.go`, the twin `NewService` doc comments, the duplicated
  "sum the quantities instead" message). Diverge wording, keep meaning. Add
  two or three pieces of honest debris (a TODO that never got done, one
  weak commit message like "fix vet complaint").
- **R8 scoped cleanup message.** "wrap the last bare errors with xerrors"
  contradicts the surviving violation in `legacy_cache.go`; scope the
  message to the orders service so skipping inventory's legacy file reads
  natural. verify.sh's "fmt.Errorf only in the legacy file" stays true.

- **R9 fictional author emails.** The bundle will be published on GitHub. All
  four personas use an obviously fictional domain (`@orderflow.example`) so no
  commit can be attributed to or auto-linked with a real person or account.
- **R10 format README.** `evals/fixtures/orderflow/README.md`: what the
  fixture is, the steps/ format (step.env, message.txt, tree/, delete.txt),
  how to run generate.sh and verify.sh, and a one-line warning that the
  materialized repo is disposable and never committed.

Update verify.sh where facts changed (dates span, commit count, any new
invariants that are cheap to assert — e.g. reflog starts with `clone:`, at
least one weekend commit, no `orders.json` in the initial commit's
.gitignore, no author email outside the fictional domain).

**Accepted, consciously not fixed** (forensic-grade tells no eval subject
will meet unprompted): loose-object mtimes beyond what clone-back fixes,
every commit building and passing tests (useful for bisect-style evals),
author==committer on most commits, a fully linear history (rebase-style
workflow is plausible for a four-person team), uniform stdlib-only test
idiom.

## Acceptance (reviewed by the orchestrator before first use)

- Double-run determinism holds on macOS.
- All `verify.sh` checks pass.
- Reading the repo cold for ten minutes does not reveal it is synthetic: no
  template-y names, no filler text, no uniform commit cadence.
- The five traps and four history facts exist exactly as specified.
